# 产品与业务流程

[返回首页](../../README.md)

## 定位与页面

面向需要管理多平台账号、API 服务、云资源和团队使用权限的小型团队。目标是让资产可登记、可查找、有归属、有责任、有使用边界，并能交接、续费和追溯。

管理员维护团队和规则，负责人维护资源，使用人从“我的资源”查找可用内容，独立确认人复核治理执行结果。在线示例账号拥有完整操作范围；正式规则仍由服务端按角色、对象和动作校验。

| 页面 | 输入/操作 | 输出与关联 |
| --- | --- | --- |
| 工作台 | 查看当前可见范围 | 资源摘要、待处理流程、到期提醒；链接到原始档案 |
| 资源清单 | 登记、筛选、关系、资料、导入导出 | 维护资源事实，供其他页面读取 |
| 我的资源 | 按责任及使用范围查看 | 同一资源详情，权限按身份计算 |
| 订阅与费用 | 周期、费用、续费、平台连接 | 关联资源；到期进入提醒，余额保留采集时间 |
| 流程治理 | 提议、执行、提供证据、独立确认 | 确认后更新资源或使用事实，保留执行轨迹 |
| 资产地图 | 选取节点与探索关系 | 同源资源及目录关系；跳转原档案 |

设置与团队用于人员、账号、角色、通知偏好等辅助维护。

## 对象模型

六层是业务分类和关系表达，不是必须依次填写的六个步骤。

| 分类 | 表达的事实 | 例子 |
| --- | --- | --- |
| L1 公司主体 | 法律或业务归属 | 某家公司 |
| L2 注册身份 | 注册、登录或找回所依赖的身份 | 公司邮箱、手机号 |
| L3 平台 | 服务提供方目录 | 云平台、协作平台 |
| L4 实际平台账号 | 真实存在的平台账户或租户 | 团队主账号 |
| L5 人员与使用关系 | 谁负责、谁使用、拥有什么权限 | 负责人、使用人、授权 |
| L6 服务与资源 | 实际购买或使用的数字资源 | 订阅、API、域名、应用、云资源 |

L4 仅在实际存在时登记。没有独立平台账号的数据库或服务，可以直接建档并关联已知主体、平台或其他资源。不会为补齐层级自动生成虚构账号。人员关系以使用/责任记录表达，不要求额外造一个“资产”。

当前资源类型：平台账号、邮箱账号、API 密钥、服务订阅、业务空间、应用系统、API 服务、云资源、域名。公司、注册身份、平台和人员目录可单独维护。

## 核心工作流

### 登记与展示

资源清单 → 登记 → 选择对象类型 → 填写最小必要事实 → 保存 → 资源详情。

关系、补充资料按已知信息维护，允许后补。按类型校验字段；关系必须符合允许的对象组合。列表展示名称、类型、归属/负责人、状态和更新时间；详细资料按任务展开。相同资源在各视图使用同一 ID 和同一事实。

### 交接与授权治理

提出变更 → 执行并补充证据 → 另一人员独立确认 → 原子更新事实并保留历史。

执行与确认不能由同一身份完成。使用版本检查避免覆盖他人更新。系统记录内部管理事实；平台上的账号权限仍需执行人实际处理并提供证据，不能把系统内确认误作外部平台权限已自动修改。

### 凭据与资料

凭据加密保存，查看前校验明确对象授权及近期认证，记录审计。普通资源 DTO、列表、CSV 不包含秘密明文。私有附件经鉴权下载，上传有格式、签名和大小限制；当前没有恶意软件扫描服务。

### 订阅与平台同步

人工维护订阅周期、续费和费用；金额按原始币种分别呈现，不直接把不同币种相加。平台连接使用独立 worker 采集余额快照，保存时间和结果，失败保留上次成功值。

首批 DeepSeek 适配器读取账户余额。它不提供每个 Key 的历史 Token 用量，也不代替人工费用账；在线实例没有配置个人真实平台 Key。

## 交互准则与当前边界

- 一个任务保留明确的主要入口，登记集中在资源清单。
- 用紧凑行、表格和分组字段提高有效信息密度，避免大卡片重复同一事实。
- 类型先行、必要信息先填、关联及扩展资料后补。
- 先呈现可操作事实，历史与补充信息按需展开。
- 空状态、无权限、版本冲突、采集失败均给出具体反馈。

当前未承诺高可用、多租户商业计费、企业 SSO、任意供应商自动接入或外部平台写权限同步。公开体验共享虚构数据，实际操作持久化；不按访问者创建隔离副本。
